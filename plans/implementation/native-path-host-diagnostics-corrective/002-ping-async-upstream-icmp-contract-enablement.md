## 1. Objective

Unblock Native M003 by turning the current upstream `ping-async` implementation into a backend that can preserve the machine evidence Eggprobe schema 0.4 already requires.

The preferred path is an additive upstream contract, not an Eggprobe-local fork and not a direct dependency on Synvoid/Eggsec.

At the planning baseline:

- crates.io/docs.rs still exposes `ping-async 1.0.2` as the published release;
- upstream `hankbao/ping-async` `master` reports source version `1.2.0` at commit `b3769ef1b1e8828cf3de14944cb2f80120b2e893`;
- upstream master already contains substantial post-1.0.2 reliability work: cancellation-safe request registration, persistent router-failure handling, Linux error-queue processing, Windows handle errors returned through `Result`, and monotonic completion timestamps;
- the remaining Eggprobe blockers are primarily public evidence loss: caller-controlled payload sizing, truthful responder identity, and a structured distinction between local deadline expiry and network-generated ICMP outcomes.

## 2. Sibling-repository disposition

The research pass MUST be treated as authoritative input unless reinspection finds new code:

- `eggstack/eggsec`: no current ICMP echo/client primitive or dependency suitable for reuse;
- `dbowm91/synvoid`: useful ICMP type/code vocabulary, filtering backends, eBPF packet parsing, and platform/socket patterns exist, but there is no reusable echo request/reply client abstraction;
- do not create an Eggprobe dependency on `synvoid-icmp-filter` or `synvoid-platform` merely to reuse constants/socket wrappers.

If a genuinely reusable cross-Eggstack ICMP primitive becomes necessary later, register a separate shared-library decision rather than copying Synvoid filter code into Eggprobe.

## 3. Existing Eggprobe contract

Schema 0.4 is already sufficient for M003 and MUST NOT be bumped by this corrective.

The relevant contract is:

- `ProbeSpec::IcmpEcho { count: 1..=10, payload_bytes: 0..=1024 }`;
- `IcmpAttempt { sequence, outcome, responder, rtt_micros }`;
- `NativeAttemptOutcome` already distinguishes `Reply`, `TimedOut`, `DestinationUnreachable`, `NetworkUnreachable`, `HostUnreachable`, and `TimeExceeded`;
- `eggprobe-native::NativeRequest::IcmpEcho { target, sequence, payload_bytes }`.

The upstream interface must preserve enough raw truth to map into these fields without inventing evidence.

## 4. Required upstream semantic surface

Exact Rust names are not prescribed. Equivalent additive API is acceptable.

### 4.1 Configurable on-wire payload length

The caller must be able to request an ICMP Echo payload length sufficient to implement Eggprobe's 0–1024-byte contract.

Requirements:

- actual on-wire echo payload length equals the requested length;
- the upstream implementation may own payload contents/correlation markers;
- internal correlation metadata must not silently increase the visible payload length;
- short payloads (including 0–7 bytes) must not defeat concurrency/cancellation/stale-reply safety;
- callers do not need arbitrary raw-packet construction.

A generic `send_with_payload(&[u8])` is acceptable, but a narrower `send_with_payload_len(usize)` is sufficient for Eggprobe and may preserve upstream's internal correlation design more cleanly.

### 4.2 Truthful responder identity

The reply must expose the address that actually generated the observed ICMP response when the platform supplies it.

Requirements:

- an echo reply may report the target when that is the observed source;
- an ICMP error generated by an intermediate router must not be mislabeled as if the target generated it;
- if the platform API cannot provide a trustworthy responder, expose `None`/unavailable rather than substituting the requested target;
- Unix `recv_from` source information and Linux error-queue offender/source metadata must be preserved where available;
- Windows native IP Helper results must be tested for their actual responder semantics rather than assumed.

### 4.3 Structured network outcome distinct from local deadline

The public reply/result must distinguish at least:

- echo reply;
- local request deadline expiry;
- ICMP Time Exceeded;
- destination/network/host unreachable when distinguishable;
- other ICMP error / unknown structured outcome.

Preserve ICMP type/code or an equivalent stable typed representation where needed for Eggprobe normalization. A backwards-compatible coarse `status()` projection may remain.

Do not classify a received Time Exceeded message as indistinguishable from a local timeout.

### 4.4 Timing and sequence

Preserve:

- sequence identity for each request;
- RTT for echo replies when measured;
- `completed_at` or equivalent monotonic outcome time;
- cancellation safety and no leaked waiter/background state.

TTL/hop-limit of the received echo reply is useful but not an M003 blocker if the platform/API cannot expose it consistently.

## 5. Future-leverage requirements

C002 is owned by the M003 unblock, but the upstream design should avoid throwing away facts useful to M005/M006.

### M005 traceroute leverage

Where possible preserve:

- requested outgoing TTL/hop limit;
- Time Exceeded as a distinct network outcome;
- actual intermediate responder address;
- per-attempt timing.

Do not expand C002 into a traceroute implementation. The acceptance question is only whether the resulting backend could support M005 without another lossy abstraction.

### M006 PMTU leverage

If the backend already observes ICMPv6 Packet Too Big, IPv4 fragmentation-needed, or Linux extended-error MTU information, preserve the raw typed fact/MTU instead of collapsing it to `Unknown`.

Cross-platform PMTU completeness is NOT a C002 closure requirement.

## 6. Ordered work packages

### WP1 — Reproduce and pin the upstream research baseline

1. Reinspect published `ping-async` and upstream `master`.
2. Record exact source commit/version, published version, license, declared MSRV if any, and target-specific dependencies.
3. Build the unmodified upstream source with Rust 1.89 on Eggprobe's supported target triples.
4. Re-run or inspect the upstream deterministic tests covering:
   - cancellation;
   - concurrent requests;
   - reply correlation;
   - Linux error queue;
   - Windows handle/error behavior;
   - loopback success.

### WP2 — Evidence-gap matrix

Create a compact matrix mapping each Eggprobe M003 evidence field/outcome to:

- already available upstream;
- internally available but discarded;
- unavailable by platform;
- requires upstream change.

The matrix MUST explicitly cover payload length, sequence, responder, RTT, deadline timeout, Time Exceeded, and unreachable classes.

### WP3 — Upstream additive API implementation

Prepare the smallest upstream patch that closes the gaps in §4.

Requirements:

- preserve existing public behavior/API where practical;
- no Eggprobe-specific schema types upstream;
- no terminal parsing;
- no process-global mutable policy;
- no panic on expected OS/permission/resource failure;
- keep async cancellation semantics intact;
- add tests before or with each new evidence field.

If contributor permissions are unavailable, produce a clean upstream-ready branch/patch and issue/PR description; do not vendor the code into Eggprobe.

### WP4 — Platform behavior verification

Use deterministic/local evidence where possible:

- Linux: loopback under an explicitly recorded `ping_group_range`/capability condition;
- macOS: loopback and cancellation/concurrency behavior;
- Windows: loopback through IP Helper APIs and handle-creation failure path;
- synthetic TTL=1 / local routed topology where available to verify that Time Exceeded is distinct from deadline expiry and that responder identity is truthful.

Public Internet traces may supplement but never substitute for deterministic evidence.

### WP5 — Upstream handoff and publication gate

1. Record upstream PR/commit/review state.
2. Do not add a git dependency to Eggprobe production manifests.
3. If upstream merges the required surface, mark C002 closed and hand off to C003, which waits for a published crates.io release containing the exact accepted interface.
4. If upstream rejects or cannot support the required semantics, stop and register an alternative backend/shared-primitive plan.

## 7. Compatibility and safety

C002 itself changes no Eggprobe runtime behavior or schema.

Upstream work must remain safe for Eggprobe to consume behind `eggprobe-native` while Eggprobe continues `unsafe_code = "forbid"`. Unsafe platform code may remain encapsulated inside the reviewed dependency.

Request payload contents are not part of Eggprobe report output.

## 8. Required verification

Record:

- Rust 1.89 build result for upstream source;
- Linux x86_64 and aarch64 target build result;
- macOS x86_64 and arm64 target build result;
- Windows x86_64 target build result;
- upstream unit/integration tests relevant to changed behavior;
- dependency/license/security review;
- exact API examples demonstrating payload length, responder, and structured network outcome.

## 9. Acceptance criteria

C002 closes only when:

1. the current upstream baseline has been requalified;
2. an accepted/merged upstream interface preserves configurable payload length, truthful responder identity, and network outcome versus local deadline;
3. cancellation/concurrency/error handling remains regression-tested;
4. Eggprobe can map the accepted API to schema 0.4 without inference or a schema bump;
5. the upstream state is recorded by immutable commit/PR evidence;
6. Eggprobe still has no git/fork production dependency;
7. C003 has a precise published-release gate.

## 10. Stop conditions

Stop and register a new decision if:

- upstream requires a breaking redesign not justified by Eggprobe;
- exact payload length cannot coexist with safe correlation semantics;
- responder identity cannot be made truthful on the platforms Eggprobe intends to qualify;
- expected OS failures can still panic;
- Rust 1.89 cannot build the accepted interface;
- satisfying the contract would require Eggprobe-authored unsafe code;
- upstream maintenance/publication state is unsuitable for a production dependency.
