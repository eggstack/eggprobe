# Subsystem Roadmaps

Subsystem roadmaps translate canonical Eggprobe direction into coherent dependency-aware workstreams. They are not coding-agent checklists.

## Naming

```text
<subsystem>-roadmap.md
```

## Required structure

Every subsystem roadmap should contain:

1. purpose and ownership boundary;
2. work classification: invariants, capabilities, infrastructure, polish;
3. non-goals;
4. current state;
5. target architecture;
6. dependency graph with hard/interface/soft/operational labels;
7. milestone definitions;
8. cross-cutting security, compatibility, cancellation, observability, performance, and documentation requirements;
9. verification strategy;
10. risks/decision points;
11. completion definition;
12. milestone-status table.

Roadmaps MUST link canonical long-term requirements rather than duplicate them wholesale, preserve completed history, and link active milestones to implementation plans and later closure records.
